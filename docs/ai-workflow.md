# AI 작업 흐름

Claude Code로 이 프로젝트를 개발하면서 쓰는 작업 흐름과, **그 흐름을 왜 그렇게 바꿨는지**를 기록한다.

`docs/checklist.md`와 `docs/context-notes.md`는 브랜치마다 덮어쓰므로 작업이 끝나면 사라진다. 여기에는 **남겨야 할 것만** 옮겨 적는다.

---

## 1. 지금의 구성

| 도구 | 종류 | 역할 |
| --- | --- | --- |
| `dev-flow` | 자작 스킬 | 조사 → 이슈 → 브랜치 → 구현 → 검증 → 리뷰 → 커밋 → PR → 기록 |
| `/code-review` | 내장 스킬 | 구현 후 빈 맥락 에이전트가 변경분을 읽고 지적 |
| `CLAUDE.md` (글로벌) | 지침 | 모든 프로젝트 공통. 8개 규칙 |
| `CLAUDE.md` (프로젝트) | 지침 | 스택·스키마·언어 규칙·커밋 컨벤션 |

전체 단계는 `.claude/skills/dev-flow/SKILL.md`에 있다.

```
① 조사·검증 → ② 이슈 → ③ 브랜치(사용자) → ④ 구현(TDD)
→ ⑤ 검증 → ⑤-b 리뷰 → ⑥ 커밋 명령어(사용자 실행) → ⑦ PR ×2 → ⑧ 학습 기록
```

## 2. 어떻게 여기까지 왔나

처음부터 설계한 흐름이 아니다. **같은 실수를 반복한 뒤에 그 자리에 단계를 놓았다.**

| 계기 | 추가한 것 |
| --- | --- |
| 커밋·머지를 AI가 실행해 되돌리기 어려웠음 | git 상태 변경은 **사용자가 직접**. AI는 명령어만 출력 |
| 브랜치를 판 뒤에야 develop이 뒤쳐진 걸 발견 (3회 반복) | ① 조사·검증에 **원격 상태 4종 확인** 고정 |
| `bundle exec brakeman`은 통과하는데 CI는 실패 | ⑤ 검증은 **`ci.yml` 원문 명령**으로. `bin/` 래퍼가 플래그를 주입한다 |
| 상태 전이 결함 3건이 프로덕션까지 감 | **⑤-b 리뷰 단계 신설** (아래 3장) |

## 3. ⑤-b 리뷰 단계를 넣은 이유

### 계기 — 테스트가 전부 그린인 채로 결함 3건이 배포됐다

PR #121(동물 프로필 사진)을 **배포까지 끝낸 뒤** `/code-review`를 돌려봤다. 상태 전이 결함 3건이 나왔다.

| 결함 | 증상 |
| --- | --- |
| `cancel()`이 표시 상태를 되돌리지 않음 | 두 번째 선택을 취소하면 이전 미리보기가 남고, 저장해도 아무것도 첨부되지 않음 |
| 디코딩 실패 경로도 같은 문제 | **서버 삭제 버튼이 다시 노출**돼, 선택 취소하려다 저장된 사진을 지우게 됨 |
| 검증 에러 재렌더 시 `blob.persisted?` 가드 | 기존 사진이 사라진 것처럼 보임 |

**이때 기존 테스트는 전부 통과하고 있었다.** request spec은 마크업이 렌더되는지까지만 본다. 클릭 이후 무엇이 보이고 숨는지는 보지 않는다.

→ 결함이 새는 자리가 확인됐으므로 **⑤ 검증과 ⑥ 커밋 사이**에 리뷰를 넣었다(PR #127).

### 설계

- **⑤ 다음** — 테스트 통과 후라 리뷰어가 동작하는 코드를 본다
- **⑥ 앞** — 수정이 별도 커밋이나 amend로 번지지 않는다
- **반박 조항** — 지적이 맞으면 수정, 아니면 **근거를 제시하고 현상유지**
- **`--fix` 금지** — 자동 적용하면 판단 단계가 사라지고, 설명할 수 없는 코드가 들어온다

반박 조항이 있는 이유는, 받아쓰기만 하면 리뷰어가 틀렸을 때 코드가 나빠지기 때문이다. 실제로 `resize_to_fill`이 동작하지 않는다고 판단할 뻔한 적이 있는데 원인은 설정이 아니라 **측정 대상을 잘못 고른 것**이었다.

## 4. 리뷰가 실제로 잡은 것

### 1회차 — `fix/photo-crop-state` (PR #127)

| 지적 | 판정 |
| --- | --- |
| system spec 헬퍼가 `page.all`을 씀 — count 옵션이 없으면 **재시도 없이 즉시 반환**. 비동기 처리 직후라 느린 CI에서 깨짐 | **수용.** `have_css` / `have_no_css`로 교체 |
| 자르기 취소가 이전 자르기 결과까지 버림 | **반박, 현상유지.** 복원하려면 확정 시점 Blob을 보관했다가 재선택·취소·디코딩 실패마다 동기화해야 한다. **이번에 고친 결함 3건이 전부 그런 동기화 누락**이었다 |

**리뷰어가 테스트 자체의 결함을 잡았다는 점**이 이 단계의 값어치를 보여준다. ⑤ 검증은 "통과했는가"만 보고 "그 통과가 믿을 만한가"는 보지 않는다. 로컬에서 4건 전부 통과한 건 **빨라서였지 맞아서가 아니었다.**

### 2회차 — `feature/animal-list-thumbnail`

| 지적 | 판정 |
| --- | --- |
| N+1 테스트 주석에 "`animal_categories` 쪽을 놓치면 카테고리 조작 후에만 N+1이 난다"고 적어놓고, **정작 그 경로를 테스트하지 않음.** 그쪽 프리로드를 지워도 전체 스위트가 그린 | **수용.** turbo_stream 경로 테스트 추가 |
| `query_count`에 `ensure`가 없어, 블록이 예외를 던지면 구독이 남아 이후 계측값이 오염됨 | **수용.** `begin/ensure`로 감쌈 |

첫 번째를 보강하면서 **두 번 더 틀렸다.**

1. 토글 대상 카테고리에 동물을 넣었더니, 토글로 그 카테고리가 숨겨져 **동물이 아코디언에서 사라졌다.** 사진을 참조하는 코드에 도달조차 못 했다
2. `Accept` 헤더를 빼먹어 `format.html`로 떨어졌다. **302 리다이렉트에 본문 길이 0**이었다

세 번 고쳐서야 실제로 결함을 잡는 테스트가 됐다. **통과하는 테스트와 검증하는 테스트는 다르다.**

## 5. 측정이 판단을 바꾼 사례

"확인했다"고 넘어갔으면 틀렸을 것들.

| 상황 | 추측 | 측정 결과 |
| --- | --- | --- |
| 부팅 실패 수정의 완료 조건 | `bin/rails -v`로 확인 | **고치기 전에도 통과한다.** 버전 출력은 앱을 부팅하지 않는다 |
| `resize_to_fill`이 안 먹는 줄 알았음 | 설정이 틀렸다 | `VariantWithRecord#blob`은 **원본**을 가리킨다. `image.blob`이 실제 variant이고 320×320으로 정상 |
| HEIC 거부 테스트 | content_type만 바꾸면 됨 | Active Storage는 **Marcel로 실제 바이트를 판정**한다. 가짜 HEIC는 통과해버린다 |
| `with_attached_photo`가 variant까지 덮는가 | 모름 | **덮는다.** 쿼리 목록에 `active_storage_variant_records`를 IN으로 긁는 줄이 있다 |
| system spec이 안정적인가 | 로컬·CI 각 1회 통과 | **불안정했다.** 5회 중 2회 실패. 원인 2개(입력 유실, 클릭 유실) |

### 수치로 남은 것

**N+1 (PR: 목록 썸네일)**

| 상태 | 동물 3마리 | 동물 10마리 |
| --- | --- | --- |
| 썸네일 전 | 7회 | 7회 |
| 썸네일 후, 프리로드 없음 | 13회 | **27회** |
| `with_attached_photo` 적용 | 11회 | **11회** |

**system spec 불안정 (PR #128, #129)**

| 원인 | 빈도 | 조치 |
| --- | --- | --- |
| `fill_in`이 비밀번호 입력을 흘림 | 12회 중 1회 | 입력 후 값을 읽어 대조, 어긋나면 재입력 |
| 다이얼로그 버튼 클릭이 핸들러에 안 닿음 | CPU 20배 스로틀에서 8회 중 1회 | 좌표를 거치지 않고 DOM click 직접 발생 |

두 번째는 **8초를 더 기다려도 안 되고 JS 예외도 없어서**, 지연이 아니라 클릭 유실임을 컨트롤러에 임시 로그를 심어 확인했다.

**파샬 추출이 화면을 바꾸지 않았음**

눈으로 훑지 않고 추출 전후 HTML을 덤프해 비교했다. 요청마다 달라지는 값(CSP nonce, UUID, Faker 이름)을 정규화하니 **20,782바이트로 길이까지 동일**했다. 234줄이 114줄이 됐고 화면은 그대로다.

## 7. 아직 안 한 것

| 항목 | 상태 |
| --- | --- |
| **그릴 단계** (구현 전에 설계를 공격) | 없음. 지금은 대화 중 비공식적으로만 일어난다 |
| **실행 흐름 설명** (변경을 사용자가 이해할 수 있게) | 없음. 보고가 파일 단위라 리뷰하기 어렵다 |
| 권한 allowlist | 없음. 모든 명령이 승인 프롬프트를 띄운다 |
| git 쓰기 차단 훅 | 없음. 규칙이 문서에만 있고 기계가 강제하지 않는다 |
| `render.yaml` 검증 훅 | 없음. CI에 이 파일 검사 job이 없다 |
| JS 동작의 자동 테스트 | 부분적. 표시 상태는 덮지만 드래그·확대는 수동 확인 |
| 목록 썸네일의 variant 생성 부하 | 미관측. 사진이 많은 관을 처음 열면 그 수만큼 libvips 변환이 3스레드 Puma 뒤에서 일어난다. `loading: "lazy"`로 한 번에 몰리는 양은 줄였고 variant는 한 번 만들면 저장되지만, 잡 워커가 없어 비동기로 뺄 방법이 없다 |

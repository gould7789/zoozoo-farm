# 코드 워크스루

**사용자가 설명할 수 없는 코드를 커밋하지 않는다.** 이 프로젝트의 전제다.

## 언제 도나

`dev-flow` ⑤-b 리뷰 다음, **⑤-d QA 앞**이다.

| 왜 리뷰 뒤인가 | 코드가 확정된 뒤라야 설명이 바뀌지 않는다 |
| --- | --- |
| **왜 QA 앞인가** | **무엇을 눌러볼지 알고** 누르게 된다 |

## 5단계 구조

순서를 지킨다. 사용자가 보는 것에서 시작해 코드로 들어간다.

### ① 무엇이 문제였나

**사용자가 보는 증상**으로 쓴다. 내부 용어로 시작하지 않는다.

```
원인   strip_tags가 블록 경계에 공백을 안 넣는다
증상   목록 발췌에서 세 줄짜리 본문이 "테스트 내용굿응?"처럼 붙어 나왔다
```

### ② 어디를 고쳤나

파일과 변경 전/후. 짧게.

```ruby
# 변경 전
strip_tags(content.body.to_html).squish.truncate(length)

# 변경 후
spaced = content.body.to_html.gsub(/<[^>]*>/, " ")
Nokogiri::HTML5.fragment(spaced).text.squish.truncate(length)
```

### ③ 이 코드가 뭔 뜻인가 ← 빠뜨리기 쉬운 단계

**기본 문법이 아닌 것은 전부 설명한다.** "알겠지"로 넘기지 않는다.

설명 대상 예시.

```
*[ ... ].compact      splat. 배열을 풀어 인자로 넘긴다
&.                    safe navigation
<<~HEREDOC            들여쓰기를 제거하는 heredoc
class_eval            클래스에 직접 메서드를 정의한다
gsub(/<[^>]*>/, " ")  태그를 '지우는' 게 아니라 '공백으로 바꾼다'
0,4,0                 CSS 명시도. 클래스 4개
data-controller       Stimulus가 파일명으로 찾는다
```

한 줄씩 끊어 읽는다.

```ruby
[ ENV["X"] ]   # → ["https://..."]  또는  [nil]
  .compact     # → ["https://..."]  또는  []      ← nil 제거
*              # 배열을 풀어서 인자로
```

### ④ 어떤 흐름으로 도나

실행 순서. **그림으로 그리면 가장 잘 읽힌다.**

```
사용자가 이미지 선택
  │
  ├─ trix-attachment-add 발생 (target: <trix-editor>)
  │
  ├─ ① 우리 리스너 (요소)       ← 여기서 가로챈다
  │     event.stopPropagation()
  │
  └─ ② 기본 리스너 (window)      ← 도달하지 않음
```

### ⑤ 왜 그 방법인가

**버린 대안을 같이 적는다.** 고른 이유보다 버린 이유가 더 많은 것을 설명한다.

```
A안  CSP를 넓힌다        → 방어가 약해진다
B안  proxy 경로를 쓴다   → 선택. 앱의 다른 이미지와 경로가 같아진다
```

## 형식

- 표와 코드 블록을 쓴다. 긴 산문을 피한다
- **그림(ASCII)** 이 글보다 나은 자리가 많다 — 흐름, 조상 체인, 경로
- 실측값이 있으면 넣는다. "빨라졌다"가 아니라 "9쿼리 → 15쿼리"

## 하지 않을 것

**변경 파일을 나열하고 끝내지 않는다.** 그건 `git diff --stat`이 한다.

**"~하도록 수정했습니다"로 끝내지 않는다.** 무엇을 했는지가 아니라 **왜 그게 동작하는지**를 설명한다.

**모르는 것을 아는 척하지 않는다.** 라이브러리 동작이 불확실하면 소스를 읽고, 읽었다고 말한다.
